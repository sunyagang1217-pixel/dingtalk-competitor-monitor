# 钉钉凭据与发送安全

## 凭据处理

- 永远不要让用户把 Webhook、`access_token` 或加签密钥粘贴到聊天。
- 永远不要把凭据放进 JSON 规格、项目文件、Git、截图、日志或命令参数。
- 本地 macOS 使用项目自带中文向导和登录钥匙串；向导使用隐藏输入，并通过标准输入把值交给钥匙串命令。
- 云端部署只使用 Secret Manager 或同时注入 `DINGTALK_WEBHOOK` 与 `DINGTALK_SECRET`。
- 凭据一旦出现在聊天、截图、公开文件或 Git 历史中，先让用户在钉钉轮换，再继续。

## 中文终端向导

运行：

```bash
./scripts/configure_dingtalk.sh
```

向导必须保持以下体验：

1. 用中文说明总步骤、预计时间和“不会发送消息”。
2. 说明从钉钉群机器人设置页复制完整 Webhook，不从聊天记录复制。
3. 输入使用 `getpass`；明确说明粘贴后终端不显示字符是正常现象。
4. 检测 `[文字](https://...)` 形式的 Markdown 超链接、缺失 `https://`、缺失 `access_token` 和错误域名。
5. 说明加签密钥应以 `SEC` 开头，并区分 AppSecret、access token 和机器人名称。
6. 每项最多重试三次；失败时给出原因和恢复步骤，不回显原值。
7. 两项均通过后才覆盖钥匙串旧值；读取校验只显示“已配置（内容已隐藏）”。
8. 最后让用户回到 Codex 回复“配置校验通过”，不要回复凭据。

## 真实发送确认

每次人工测试或首次正式日报发送前，展示并确认：

1. 目标：当前 Webhook 绑定群；如果无法从 Webhook 确定群名，明确说无法确定，不猜测。
2. 完整标题与完整正文。
3. `@` 行为；默认不 `@` 任何人。
4. 这次操作会产生真实群消息。

没有明确确认时，只运行 `preview` 或 `analysis-preview`。确认后使用固定口令保护的项目命令；命令中只包含已确认的消息内容和固定口令，不包含凭据。

真实发送后只保留钉钉返回的错误码和状态。不要输出已加签 URL，因为它包含 access token 和签名。

## 定时发送授权

定时任务会在未来产生外部消息。创建前单独展示目标群、时间、星期、行业范围、竞品范围、日报格式、最大条数、来源核验、去重和 `@` 行为，并明确说明自动发送是否需要逐次确认。

用户未明确授权“符合这些边界的日报可自动发送”时，自动化必须停在草稿预览，不执行发送。用户授权后也不得扩大目标群、监控范围、频率或 `@` 行为；任何边界变化都要重新确认。

自动发送只能调用项目的 `send-analysis --confirm SEND_TO_DINGTALK`，固定不 `@`。不要改用通用 `send`、`curl`、其他 Webhook 或其他消息渠道。只有返回 `status=sent` 且 `errcode=0` 才视为成功；`status=already_sent` 时不得重发，其他结果不得写成发送成功。
